# 00. 전체 아키텍처 개요

## 목표
착용자가 보고 있는 **세계 좌표계상의 3D 지점**을 실시간으로 추정한다.
= 시선 방향(눈) × 깊이(스테레오) × 머리 pose(SLAM) 의 융합.

## 데이터 흐름
```
┌─────────────┐    IR 눈 영상      ┌──────────────┐
│ 눈 카메라    │ ─────────────────▶ │ 동공 검출     │  pupil-detectors + pye3d
│ (OV9281/IR) │                    │ → 시선벡터    │  (3D 안구모델)
└─────────────┘                    └──────┬───────┘
                                          │ (u,v) 시선 픽셀  ← 캘리브레이션 매핑
                                          ▼
┌─────────────┐   스테레오 L/R     ┌──────────────┐
│ 스테레오     │ ─────────────────▶ │ 스테레오매칭  │  StereoSGBM (시선 주변 윈도우만)
│ (oCamS)     │                    │ → 깊이 D      │
│  + IMU      │ ─────────────────▶ │ ORB-SLAM3 VI │  → pose T_WS
└─────────────┘                    └──────┬───────┘
                                          ▼
                                   ┌──────────────┐
                                   │  융 합        │  p_W = T_WS · (D·K⁻¹[u,v,1])
                                   │              │  시선광선 = pose중심 → p_W
                                   └──────┬───────┘
                                          ▼
                                     시각화 / 저장
```

## 변환 사슬 (핵심)
1. **시선 픽셀**: 캘리브레이션 매핑으로 눈 시선 → 스테레오 이미지 픽셀 `(u,v)`
2. **역투영**: 그 픽셀의 스테레오 깊이 `D` → 카메라 좌표 3D점 `p_S = D · K⁻¹ [u,v,1]ᵀ`
3. **월드 변환**: 해당 타임스탬프 pose로 `p_W = T_WS · p_S`
4. **시선 광선**: 원점 = pose translation, 방향 = `normalize(p_W − 원점)`

"얼마나 떨어졌나" = 그냥 `D`. 눈과 스테레오 카메라가 머리 위 몇 cm 차이라
눈→대상 거리 ≈ 카메라→대상 거리로 봐도 실용상 무방.

## 역할 분담
- **Pi (엣지)**: 센서 캡처 + 동공검출(경량, 센서 전처리 성격) + 스트리밍. "주 처리"가 아니라 "대역폭 절약".
- **데스크톱**: SLAM + 융합 + 시각화 (무거운 연산).

## 통신 하이브리드
- **영상**: GStreamer RTP/UDP (저지연). ROS2 이미지 토픽 Wi-Fi 직송은 DDS 디스커버리/QoS 문제로 큰 데이터에 약함.
- **제어 / 시선벡터 / pose**: ROS2 토픽.
