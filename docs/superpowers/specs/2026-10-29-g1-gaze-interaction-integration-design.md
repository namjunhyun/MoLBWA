# G1 교감 데모 통합 인터페이스 설계

2026-10-29 · 팀 MoLBWA / 남준현 · 대상: G1 '지원이' 최종 교감 데모

## 1. 목표와 성공 기준

착용형 아이트래킹 안경을 쓴 사용자의 **시선**으로 G1 로봇과 교감하는 데모를, 흩어져 있는 부품(웹 패널·CLOVA 대화·시선/YOLO·로봇 명령)을 **하나의 통합 인터페이스**로 엮어 완성한다.

데모 시나리오:
1. 사용자가 로봇을 보면 로봇이 **사용자 쪽으로 돈다**.
2. 로봇 **얼굴을 3초 보면 인사**(손 흔들기), **손을 3초 보면 악수**.
3. 주변 물체(화분·꽃·인형·휴대폰 등)를 **3초 보면**, 로봇이 같이 그 물체를 보고(attend) **CLOVA로 그 물체에 대해 말을 건다**.

성공 기준:
- 시선만으로(수동 조작 없이) 위 3가지가 자동 발동.
- 한 프로세스에서 비상정지·상태·대화로그가 보이는 웹 UI로 운영.
- 실기에서 안전하게 동작(비상정지 상시, 정책 구동 중 DDS 충돌 없음).

## 2. 설계 결정 (사용자 확정)

- **트리거**: 일정 시간 **응시(dwell)**. 흘깃 보는 것과 구분, fixation 기반 설계와 일치. 기본 3초(기존 `g1_interaction_node`의 `dwell_time`와 동일).
- **물체 검출**: **COCO YOLO**(`yolo11l.pt`)로 되는 물체만 사용. 가족사진 액자는 일반 YOLO에 없으므로 인형·화분으로 대체.
- **통합 구조**: **웹 패널 중심**. `g1_interaction_node`의 dwell→동작 로직을 패널 프로세스 안으로 흡수해, 자동 노드와 패널의 포트(55071) 충돌을 없앤다.
- **우선순위**: 얼굴/손(사람 교감) > 물체(대화). 둘 다 응시 후보면 사람 교감 먼저.

## 3. 아키텍처

### 3.1 데이터 흐름

```
눈카메라→동공→씬투영 (gaze_on_scene.py)
        │  시선픽셀 u,v (UDP 55056)
        ├────────────────→ g1_gaze_bridge.py ──→ 부위 label + bearing_deg + obj_bearing_deg (UDP 55057)
        └────────────────→ [새] 물체 YOLO 워커 ──→ 응시 물체 label + bearing
                                                         │
                               [새] 오케스트레이터 (패널 프로세스 내 스레드)
                                   · 55057 부위 이벤트 수신
                                   · 물체 이벤트 수신
                                   · 상태기계로 분기
                                                         │
                               act / attend+Dialog.start / say  (UDP 55070)
                                                         │
                               g1_motion_server.py (젯슨) ──→ state (UDP 55071) ──→ 패널 표시
```

기존 포트·프로토콜을 그대로 재사용한다(`docs/g1_dialog_interface.md`). 바뀌는 것은 "누가 55070 명령을 내느냐"뿐 — 기존엔 `g1_interaction_node`(act만)와 패널(수동)이 각각, 이제는 **패널 내 오케스트레이터 하나**.

### 3.2 컴포넌트 (각 단위의 역할·인터페이스·의존)

**A. [새] 대화용 물체 검출 — `g1/obj_gaze_detector.py`**
- **역할**: 씬영상에서 COCO YOLO로 대화 대상 물체를 검출하고, 시선픽셀(u,v)이 들어있는 박스를 골라 "지금 응시 중인 물체 라벨 + 화면상 방위"를 낸다.
- **입력**: ROS `/pc/camera/left/compressed`(씬영상), UDP 55056(시선픽셀). **출력**: 콜백 또는 내부 큐로 `{label, bearing_deg, valid}`를 오케스트레이터에 전달.
- **의존**: 기존 `gaze_hri/yolo_worker.py`(ultralytics, stdin JPEG→stdout dets) 재사용. 모델 `yolo11l.pt`. 클래스 `[potted plant, vase, teddy bear, bottle, cup, cell phone]`.
- **방위**: 부위 bearing과 일관되게, 박스 중심 픽셀을 헤드캠 내부파라미터로 역투영해 torso 좌표 방위 산출(gaze_bridge의 `object_bearing_deg` 재사용). 또는 간단히 obj_bearing_deg(55057)를 그대로 쓰되, 그 값은 부위가 null일 때만 유효하므로 물체 검출기가 자체 산출하는 쪽이 안전 — 구현 계획에서 확정.
- **왜 분리**: 로봇 부위 YOLO(`g1_parts.pt`)와 물체 YOLO(`yolo11l.pt`)는 다른 모델이라 한 워커에 못 합침. 별도 워커로 둔다.

**B. [새] 오케스트레이터 — `g1/g1_orchestrator.py`**
- **역할**: 시선 이벤트(부위+물체)를 받아 상태기계로 로봇 명령을 낸다. `g1_interaction_node`의 `LabelDwell`을 재사용·확장.
- **입력**: UDP 55057(부위 label+bearing), 컴포넌트 A의 물체 이벤트, UDP 55071(로봇 state로 busy 판정). **출력**: UDP 55070(act/attend/say), CLOVA 대화 시작(`Dialog.start`).
- **의존**: `g1_protocol`(명령 pack), `g1_dialog.Dialog`(대화), `g1_say`(발화).
- **상태기계**:
  - `IDLE`: 부위·물체 응시 감시. 부위(얼굴/손)가 물체보다 우선.
  - 얼굴 dwell 3초 → `act(part=g1_face)` = 사용자 쪽 회전 + 손 흔들기 → `BUSY`.
  - 손 dwell 3초 → `act(part=g1_hand)` = 회전 + 악수 → `BUSY`.
  - 물체 dwell 3초 → 라벨→kind 매핑 → `attend`(물체쪽 보고 착용자쪽 복귀) + `Dialog.start(kind, with_attend=True)` → `BUSY`.
  - `BUSY`: 로봇 동작/대화 진행 중. 새 트리거 무시. 동작 끝(state=idle) + 대화 끝나면 `IDLE`로.
- **dwell 리셋**: 응시 라벨이 바뀌거나 무효 프레임이 오면 카운터 리셋(기존 `LabelDwell` 로직).

**C. [수정] 웹 패널 — `g1/g1_panel.py`**
- **추가**: "자동 교감 모드" 토글 버튼.
  - ON: 오케스트레이터 스레드 시작. 수동 동작/대화 버튼은 비활성(충돌 방지).
  - OFF: 오케스트레이터 정지. 기존 수동 버튼 복귀.
- **유지**: 비상정지·정지·정책 ON/인계/반납/종료(SSH), 로봇 state 표시, 대화 로그, 위험신호 alert — 자동/수동 무관하게 항상.
- **포트 충돌 해소**: 오케스트레이터가 패널 프로세스 안 스레드이므로, 별도 `g1_interaction_node`(55071 중복 bind)를 띄우지 않는다. 55071 수신은 패널이 단독.

### 3.3 물체 → 대화 시나리오 매핑

| YOLO 라벨 | kind (SCENARIOS) |
|---|---|
| potted plant, vase | `plant` (화분) |
| bottle, cup | `bottle` (물병) |
| cell phone | `phone` (휴대폰) |
| teddy bear | `photo` (가족사진 시나리오를 인형 대상으로) |

- `teddy bear → photo`는 가족사진 액자가 YOLO에 없어 인형으로 대체한 것. 대화 멘트가 "가족사진"을 전제하면 어색할 수 있어, `photo` 시나리오의 첫 문장을 물체 중립적으로 조정하거나 인형 전용 짧은 시나리오를 추가할지는 구현 중 확인(시나리오는 `g1_dialog.SCENARIOS` 데이터만 손대면 됨).

## 4. 에러 처리·안전

- **비상정지 상시**: 자동 모드에서도 패널 비상정지(damp)는 항상 최우선.
- **BUSY 게이트**: 로봇이 움직이거나 대화 중이면 새 트리거 무시. 동작 겹침·명령 폭주 방지. 기존 프로토콜의 "동작 중 act/attend 무시"와 일치.
- **DDS 충돌 방지**: 정책 구동 중 다른 프로세스가 젯슨 DDS를 새로 열면 제어주기가 깨짐(실기 확인된 문제). 오케스트레이터는 UDP만 쓰고 DDS를 직접 열지 않는다. numpy 1스레드 환경 유지.
- **대화 중 로봇**: attend는 대화 시작 시 1회만. 이후엔 발화(say)만, 큰 동작 없음.
- **시선 끊김**: 무효 프레임(valid=false)이 연속되면 dwell 리셋, 오동작 방지. 로봇은 마지막 상태 유지(새 명령 안 냄).

## 5. 테스트

- **단위**: 오케스트레이터 상태기계 — 가짜 시선 이벤트 시퀀스(얼굴 3초, 손 3초, 물체 3초, 중간 라벨 변경, busy 중 트리거)를 넣어 올바른 55070 명령/대화 호출이 나오는지. 기존 `test_g1_protocol.py`·`test_g1_dialog.py` 패턴 재사용.
- **물체 검출**: 샘플 이미지 + 시선픽셀로 올바른 라벨·방위가 나오는지.
- **통합(로봇 없이)**: 가짜 relay/젯슨 스텁으로 55070 명령 흐름 확인. 패널 토글→오케스트레이터 기동/정지.
- **실기**: sim/드라이런 검증 후, 비상정지 대기 상태에서 단계적으로. 안전 수칙 준수.

## 6. 범위 밖 (YAGNI)

- 가족사진 액자 전용 검출(YOLO-World 등) — 인형·화분으로 대체.
- 스테레오 깊이 기반 3D 물체 위치 — 데모엔 방위(bearing)면 충분, 거리는 가정값(1.5m) 유지.
- 팔 pick-place 트랙(`task_manager_node`) 연동 — 별개 데모.
- SLAM 세계좌표(55055) 경로 — 이 데모에 불필요.
