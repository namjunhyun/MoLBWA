# 2026-07-23 — gaze_on_scene.py 캘리브레이션 개선

`src/gaze_on_scene.py`에 씬 카메라 반전 옵션 + 다점(마우스 클릭) 캘리브레이션 + fx 자동보정을 추가.
커밋: `c74101f`

## 배경

기존 1점 캘리브(`c` 키)는 "지금 순간의 시선벡터 = 씬 카메라 정면"으로 놓는 회전 R 하나만
구하는 방식(Rodrigues 최소회전). 벡터쌍이 1개뿐이라 캘리브 지점에서 각도가 멀어질수록
오차가 커지는 한계가 있었다 (`docs/01_eye_tracking.md`의 "캘리브레이션 = 정확도의 90%"
섹션에서 지적한 문제와 동일한 맥락).

## 추가된 것

### 1. `--scene-flip`
oCamS가 거꾸로 장착된 경우 씬 영상을 180도 반전 (`cv2.flip(scene, -1)`). 카메라가 광축
중심으로 180도 돌아간 경우, 원점(cx,cy)이 그대로 이미지 중심이라 핀홀 투영 수식은
안 건드려도 됨.

### 2. 다점 캘리브레이션 (`m` 키)
실제 물체/점을 씬 카메라 앞에 두고 그걸 응시한 상태에서, 화면상 그 물체의 실제 위치를
마우스로 클릭 → (그 순간의 시선벡터, 클릭 픽셀) 쌍을 수집. 점이 2개 이상 모이면 매번
**Wahba's problem**(Kabsch/SVD)으로 전체 잔차를 최소화하는 회전 R을 다시 계산.

- 클릭한 지점은 화면에 자홍색 십자 + 번호로 계속 표시됨.
- 1점 캘리브(`c`)는 그대로 남겨둠 — 빠른 사전 정렬용으로 유효.
- `r`로 리셋하면 다점 포인트도 같이 초기화.

### 3. fx(초점거리) 자동 보정 — 점 3개 이상일 때
기존엔 `--fx` 근사값(`SW*0.94`)을 고정으로 썼는데, 이 값이 틀리면 회전을 아무리 정확히
맞춰도 화면 중심에서 멀어질수록 재투영 오차가 커지는 형태로 나타난다 (회전만으로는
스케일 오차를 못 없앰).

점이 3개 이상이면 fx 후보마다 **그때그때 최적 R을 다시 풀어(nested grid search)** 실제
클릭 픽셀과의 재투영 오차가 가장 작은 fx를 좁혀나간다. 후보 fx를 고정한 채 R만 한 번
구하고 끝내는 방식(좌표하강)은 국소최적에 갇혀서 못 씀 — 매 후보마다 R을 다시 풀어야
전역적으로 수렴함 (합성 데이터로 검증: N≥3에서 노이즈 없는 경우 재투영오차 0으로 수렴).

## 사용법

```bash
python src/gaze_on_scene.py --scene-flip
```

씬 카메라 창에서:
1. `m` → 다점 캘리브 모드 ON
2. 실제 지점 응시 + 그 위치 클릭 (반복, 화면 여러 구역에 고르게)
3. 2점째부터 자동으로 R 재계산, 3점째부터 fx도 같이 최적화됨
4. `r`로 전체 리셋 (fx도 초기 근사값으로 복원)

## 알려진 한계

- 회전+스케일(fx) 보정이라 눈↔씬 카메라 사이 물리적 위치 차이(패럴랙스)는 여전히
  못 잡음 — 캘리브한 거리와 실사용 거리가 많이 다르면 오차 남음. 진짜 해결은
  `docs/03_fusion.md`의 스테레오 깊이 + SLAM pose 파이프라인.
- 눈 카메라 캘리브 CAD 좌표는 `glasses.stl`에 없음 (oCamS 마운트만 모델링됨, 눈 카메라는
  이 CAD 버전엔 반영 안 됨) — 기구적 실측으로 extrinsic을 구하는 경로는 아직 불가.
