# 로봇 단독 개발·테스트 절차

안경 없이 로봇 쪽만 완성하기 위한 단계별 절차입니다.
마우스 클릭이 시선을 대신하고, 탑다운 카메라가 좌표를 만듭니다.
SLAM도 IR 카메라도 필요 없습니다.

**각 단계마다 "통과 기준"이 있습니다. 통과 못 하면 다음으로 넘어가지 마세요.**
앞 단계가 틀린 채로 진행하면 뒤에서 원인을 찾느라 며칠 날립니다.

---

## 전체 그림

| 단계 | 하는 일 | 하드웨어 | 예상 시간 |
|---|---|---|---|
| 0 | 물리 세팅 고정 | 카메라·로봇·책상 | 반나절 |
| 1 | 빌드 + 숫자 채우기 | — | 1시간 |
| 2 | 서보 개별 검증 | 로봇 | 반나절 |
| 3 | 호모그래피 캘리브레이션 | 카메라+로봇 | 30분 |
| 4 | 좌표 검증 (dry_run) | 카메라 | 1시간 |
| 5 | 재시도 로직 검증 | — | 30분 |
| 6 | 실제 파지 | 전부 | 1일 |
| 7 | 성공률 측정·튜닝 | 전부 | 1일 |
| 8 | 안경과 통합 | 전부 | 반나절 |

# 0단계 — 물리 세팅을 먼저 고정한다

**소프트웨어보다 이게 먼저입니다.** 3단계 캘리브레이션은 카메라와 로봇의
상대 위치를 기억하는 작업이라, 나중에 하나라도 움직이면 전부 다시 해야 합니다.

체크리스트:

- [ ] 로봇을 책상에 **클램프나 양면테이프로 고정**. 손으로 밀어서 안 움직여야 함
- [ ] 탑다운 카메라를 삼각대나 클램프로 고정. 책상 전체가 화면에 들어오게
- [ ] 카메라 화면에 로봇 베이스와 작업 영역이 **둘 다** 보이는지 확인
- [ ] 조명 고정. 창가면 커튼 치기 (시간대에 따라 색이 변하면 검출이 깨짐)
- [ ] 시연용 컵 **한 종류로 확정**. 원통형, 지름 7~8cm, 손잡이 없음
- [ ] 컵 바닥에 동전이나 너트를 넣어 무게중심 낮추기
- [ ] USB 케이블 정리. 로봇이 움직일 때 안 걸리게

카메라 위치는 **정확히 수직일 필요 없습니다.** 호모그래피가 비스듬한 각도도
보정합니다. 다만 각도가 너무 크면 컵끼리 서로 가리므로 60도 이상은 유지하세요.

> **통과 기준**: 책상을 한 바퀴 돌며 흔들어도 카메라·로봇이 안 움직임.
> 화면에 작업 영역 전체와 로봇 베이스가 보임.

# 1단계 — 빌드하고 숫자를 채운다

```bash
pip install opencv-python
cd ~/gaze_ws
colcon build --symlink-install
source install/setup.bash
```

## 채워야 할 숫자 1: 링크 길이

`config/gaze_hri.yaml`의 다섯 개 값입니다. **기본값은 추정치라 반드시 바꿔야 합니다.**

```yaml
base_height: 0.0563      # 베이스 바닥 -> 어깨 관절축까지 높이
shoulder_offset: 0.0304  # 회전축 -> 어깨 관절축까지 수평 거리
l1: 0.1160               # 어깨 -> 팔꿈치
l2: 0.1350               # 팔꿈치 -> 손목
l3: 0.1100               # 손목 -> 그리퍼 파지 중심
```

두 가지 방법이 있습니다.

**방법 A (정확)**: SO-ARM101 URDF의 `<joint><origin xyz="...">` 값을 읽습니다.

```bash
ros2 launch so_arm101_description display.launch.py
# 또는 URDF 파일을 직접 열어서 각 joint의 origin 확인
```

**방법 B (빠름)**: 팔을 쭉 편 상태에서 자로 잽니다. 관절 중심에서 관절 중심까지.
오차 2~3mm는 괜찮습니다. 나중에 카메라가 보정합니다.

`l3`는 특히 주의하세요. **그리퍼 끝이 아니라 물체를 실제로 무는 지점**까지입니다.
손가락을 닫았을 때 물체 중심이 오는 자리를 재세요.

## 채워야 할 숫자 2: 카메라 인덱스

```bash
ls /dev/video*
python3 -c "import cv2; c=cv2.VideoCapture(0); print(c.read()[0])"
```

## 채워야 할 숫자 3: 테이블 높이

로봇이 책상 위에 직접 놓여 있다면 `table_z: 0.0`이 맞습니다.
받침대 위에 있다면 책상면이 로봇 기준으로 음수가 됩니다.

```yaml
table_z: 0.0                          # topdown_click
table_plane: [0.0, 0.0, 1.0, 0.0]     # target_resolver. z=0 평면이면 그대로
```

> **통과 기준**: `colcon build` 에러 없음.
> `ros2 pkg list | grep gaze` 에 두 패키지가 보임.

# 2단계 — 서보를 하나씩 검증한다

**여기를 건너뛰면 뒤에서 로봇이 이상하게 움직여도 원인을 못 찾습니다.**

## 2-1. 연결 확인

```bash
ls /dev/ttyACM*                      # 또는 /dev/ttyUSB*
sudo usermod -a -G dialout $USER     # 한 번만. 재로그인 필요
```

## 2-2. 방향과 중립 확인

```bash
# 터미널 1
ros2 run gaze_hri arm_server --ros-args \
  --params-file src/gaze_hri/config/gaze_hri.yaml -p backend:=feetech

# 터미널 2 — 어깨만 좌우로
ros2 topic pub --once /arm/goto_joints std_msgs/Float64MultiArray \
  "{data: [0.5, -0.6, 1.2, -0.6, 0.0, 1.2]}"
```

| 확인 | 틀렸을 때 |
|---|---|
| `shoulder_pan` 양수 → 왼쪽으로 도나 | `servo_signs[0]`을 -1로 |
| 값이 전부 0일 때 팔이 곧게 서나 | `servo_offsets`로 중립 보정 |
| 각 관절이 URDF 방향과 맞나 | 해당 `servo_signs` 뒤집기 |
| 그리퍼 열림/닫힘이 맞나 | `servo_signs[5]` 또는 open/closed 값 교환 |

**속도를 낮춰서 하세요.** `FeetechBackend`의 `speed=600`을 300으로 줄이면
이상할 때 손으로 잡을 시간이 생깁니다.

## 2-3. 순기구학 검증 — 이 단계가 가장 중요합니다

```bash
ros2 topic pub --once /arm/goto_joints std_msgs/Float64MultiArray \
  "{data: [0.0, -0.5, 1.0, -0.5, 0.0, 0.8]}"
```

이 자세에서 그리퍼 파지 중심이 실제로 어디인지 **자로 재세요.**
로봇 베이스 중심 기준으로 앞으로 몇 cm, 위로 몇 cm인지.

계산값과 비교합니다.

```bash
python3 -c "
import sys; sys.path.insert(0,'src/gaze_hri')
from gaze_hri.kinematics import ArmGeometry, forward_kinematics
print(forward_kinematics([0,-0.5,1.0,-0.5], ArmGeometry()))
"
```

> **통과 기준**: 계산값과 실측값 차이 **10mm 이내**.
> 넘으면 링크 길이가 틀린 겁니다. 1단계로 돌아가세요.
> **이걸 넘기고 진행하면 뒤에서 절대 못 맞춥니다.**

# 3단계 — 호모그래피 캘리브레이션

## 원리

책상은 평면입니다. 위에서 보는 카메라와 평면 사이에는 3×3 행렬 하나로
표현되는 관계가 성립합니다. 즉 **화면 픽셀 → 로봇 좌표**가 행렬 곱 한 번으로 끝납니다.
깊이도 SLAM도 필요 없습니다.

캘리브레이션은 **로봇 자신을 자로 씁니다.**

1. 팔을 정해진 자세로 보냄 → 순기구학으로 손끝 로봇 좌표를 정확히 앎
2. 그 손끝이 화면 어느 픽셀인지 사람이 클릭
3. 네 쌍 이상 모이면 `cv2.findHomography`가 행렬을 뱉음

## 실행

```bash
ros2 launch gaze_hri robot_only.launch.py mode:=calib backend:=feetech
```

로봇팔이 6개 자세를 차례로 잡습니다. 매번 **화면에서 그리퍼 끝을 클릭**하세요.

클릭 요령:
- 그리퍼 **손가락 끝 사이 중앙**(파지 중심)을 클릭
- 창을 크게 키워놓으면 정확도가 올라갑니다
- 잘못 클릭했으면 `c`로 직전 것 취소 후 다시

## 결과 확인

```
완료. 재투영 오차 4.2 mm
저장: ~/.ros/topdown_homography.yaml
```

| 오차 | 판정 |
|---|---|
| 5mm 이하 | 좋음 |
| 5~15mm | 사용 가능 |
| 15mm 초과 | **재작업** |

오차가 크면:
- 2단계 순기구학 검증을 제대로 했나
- 클릭 지점이 그리퍼 끝이 맞나 (손목이나 손가락 뿌리를 찍지 않았나)
- 캘리브 지점이 한 직선 위에 몰리지 않았나

> ### ⚠️ 이 숫자를 믿지 마세요 — 반드시 4단계로 검증하세요
>
> 재투영 오차는 **캘리브 점 자신에 대해서만** 맞춘 숫자입니다.
> 실사용 정확도를 보증하지 **않습니다.**
>
> 초안은 캘리브 자세를 관절각으로 적어뒀는데, 그 자세들의 그리퍼 끝 높이가
> 95.8mm 폭으로 흩어져 있었습니다(3.6~13.1cm). 호모그래피는 평면↔평면 대응이라
> 캘리브 점이 전부 같은 높이여야 하는데 말이죠.
>
> 같은 격자(테이블면 56점)에서 수정 전후를 비교한 결과입니다:
>
> | 카메라 | 재투영 (화면에 찍히는 값) | 실제 테이블면 오차 |
> |---|---|---|
> | 수직 — 수정 전 | 3.7mm → "좋음" | 평균 17.9 / 최대 44.7mm |
> | 수직 — 수정 후 | 0.0mm | 평균 **0.50** / 최대 0.83mm |
> | 15도 — 수정 전 | 4.2mm → "좋음" | 평균 57.5 / 최대 149mm |
> | 15도 — 수정 후 | 0.0mm | 평균 **1.86** / 최대 2.66mm |
> | 30도 — 수정 전 | 9.4mm → "사용 가능" | 평균 372mm (파탄) |
> | 30도 — 수정 후 | 0.0mm | 평균 **3.54** / 최대 4.43mm |
>
> **지금은 고쳐져 있습니다.** 캘리브 지점을 테이블면 위 (x, y)로 적어두고
> 관절각을 역기구학으로 풀기 때문에 높이가 전부 같습니다(폭 0.00mm).
>
> 그래도 4단계의 자 검증은 건너뛰지 마세요. 링크 길이가 틀렸거나 카메라가
> 움직였으면 이 숫자는 여전히 거짓말을 합니다.

> **통과 기준**: 재투영 오차 **15mm 이하**, **그리고 4단계 실측 통과.**

# 4단계 — 좌표 검증 (서보 끄고)

**서보를 켜기 전에 반드시 여기를 통과하세요.**

```bash
ros2 launch gaze_hri robot_only.launch.py
```

## 4-1. 화면 좌표 검증

화면 아무 곳이나 클릭하면 커서 옆에 로봇 좌표가 뜹니다.
**자를 대고 실제 거리를 재서 비교하세요.** 최소 5군데:

- 로봇 바로 앞
- 왼쪽 끝, 오른쪽 끝
- 가장 먼 곳
- 화면 구석 (여기가 오차가 제일 큽니다)

## 4-2. 파이프라인 흐름 확인

```bash
ros2 topic echo /gaze/point_raw    # 커서 움직이면 계속 나와야 함
ros2 topic echo /gaze/fixation     # 클릭했을 때만 한 번
ros2 topic echo /gaze/target       # 최종 목표 좌표
ros2 topic echo /task/state        # IDLE -> PICK_SELECTED -> EXECUTING
```

신호가 어디서 끊기는지 보면 문제 지점이 바로 나옵니다.

## 4-3. IK 확인

`arm_server` 터미널에 관절 각도가 찍힙니다.

```
[APPROACH_PICK]
  [dry-run] 관절각(deg): [ -12.3,  -28.5,   62.1,  -33.6,    0.0,   68.8]
```

각도가 상식적인지 보세요. 200도 같은 값이 나오면 뭔가 틀린 겁니다.

`역기구학 실패: 작업 공간 밖`이 뜨면 컵을 로봇 쪽으로 당기세요.
베이스 반경 15cm 이내는 이 팔 구조상 도달 불가입니다.

> **통과 기준**: 5개 지점 모두 실측과 **10mm 이내**.
> 클릭 → 클릭 → `EXECUTING`까지 상태가 흐름. IK 실패 없음.

# 5단계 — 재시도 로직 검증 (여전히 하드웨어 없이)

파지를 일부러 실패시켜서 복구 동작을 확인합니다.

```bash
ros2 launch gaze_hri robot_only.launch.py fail_rate:=0.5
```

로그에서 볼 것:

```
파지 확인: 명령 0.150 / 실제 0.020 (차이 -0.130, 기준 0.080) -> 빈손
파지 재시도 2/3
```

- 실패를 감지하는가
- 재시도할 때 목표를 조금씩 옮기는가
- 3회 다 실패하면 홈으로 복귀하고 액션이 abort 되는가

`fail_rate:=1.0`으로 하면 무조건 실패하니 복구 경로만 집중해서 볼 수 있습니다.

> 초안에서는 이 단계가 **실행 자체가 불가능**했습니다. dry-run 백엔드가 파지
> 성공 시 명령값을 그대로 돌려줘서 차이가 0이 나왔고, 그래서 `fail_rate`와
> 무관하게 **항상 "빈손"** 판정이었습니다(2000회 시도 중 0회 성공).
> 4단계도 매번 3회 재시도 후 abort로 끝났습니다.
> 지금은 고쳐져서 `fail_rate` 0.0 / 0.5 / 1.0이 각각 100% / 50% / 0% 성공으로
> 정확히 반영됩니다.

> **통과 기준**: 3회 실패 후 팔이 홈으로 돌아가고
> `task_manager`가 `IDLE`로 복귀. 이상한 자세로 멈추지 않음.

# 6단계 — 실제 파지

**안전 준비부터:**

- [ ] 전원 스위치를 손 닿는 곳에
- [ ] 팔을 손으로 잡을 수 있는 자세로 앉기
- [ ] 첫 시도는 컵 없이 (허공에서 동작만 확인)
- [ ] 주변에 깨질 물건 치우기

```bash
ros2 launch gaze_hri robot_only.launch.py backend:=feetech
```

## 6-1. 파지 높이 맞추기

`grasp_height`는 테이블에서 파지 중심까지 높이. 컵 높이의 절반 정도입니다.

```yaml
target_resolver:
  ros__parameters:
    grasp_height: 0.045     # 9cm 컵이면 4.5cm
```

**컵을 바꾸면 반드시 다시 재세요.**

## 6-2. `grasp_margin` 실측

파지 감지의 핵심 값입니다. 추측하지 말고 재세요.

```bash
ros2 topic echo /joint_states
```

1. 컵을 물린 상태에서 `gripper` 값 기록 → 예: `0.31`
2. 빈손으로 닫았을 때 값 기록 → 예: `0.16`
3. 차이(0.15)의 **절반**을 `grasp_margin`에 → `0.08`

## 6-3. 부하 검사 (선택)

더 확실하게 하려면 부하도 봅니다. 컵을 물린 상태의 부하값을 확인하고
그 절반쯤을 `min_grasp_load`에 넣으세요. `0`이면 검사하지 않습니다.

> **통과 기준**: 컵 있을 때 "물었음", 없을 때 "빈손"으로 정확히 판정.
> 10회 중 판정 오류 0회.

# 7단계 — 성공률 측정과 튜닝

여기서 나온 숫자가 **보고서에 그대로 들어갑니다.**

## 측정 방법

컵 위치를 매번 바꿔가며 30회 시도하고 기록합니다.

| 항목 | 기록 |

| 1차 시도 성공 | __ / 30 |

## 목표치

|---|---|---|
| 재시도 포함 성공률 | 80% | 95% |
| 1차 성공률 | 60% | 85% |

## 성공률이 낮을 때, 효과 큰 순서로

1. **깔때기 그리퍼** — 손가락 안쪽을 V자로. 허용 오차가 두 배. 효과 최대
2. **마찰 패드** — 손가락 안쪽에 실리콘/고무. 미끄러짐 감소
3. **컵 무게 늘리기** — 바닥에 너트. 넘어짐 방지
4. **`approach_pitch` 조정** — "안 되면 더 가파르게"가 아닙니다. 각도마다
   닿는 거리 띠가 다릅니다: 75도 → 0.20~0.29m, 45도 → 0.26~0.35m,
   20도 → 0.30~0.38m. **컵이 가까우면 가파르게, 멀면 얕게** 잡으세요.
   (코드는 여러 각을 자동으로 시도하므로 보통은 손댈 필요가 없습니다)
5. **`grasp_height` 재조정** — 너무 높으면 테두리를 침
6. **비주얼 서보잉** — 손목 카메라로 하강 직전 미세 정렬. 여유 있을 때

> **통과 기준**: 재시도 포함 성공률 **80% 이상**.

# 8단계 — 안경과 통합

로봇 쪽이 7단계를 통과했다면, 통합은 **두 가지만 바꾸는 일**입니다.

## 무엇이 바뀌나

| | 로봇 단독 | 통합 후 |
|---|---|---|
| 좌표 출처 | 마우스 클릭 | 시선 (`gaze_bridge`) |
| `map` ↔ `base_link` | 항등변환 | `T_BW` 캘리브레이션 |
| 컵 정확한 위치 | 탑다운 | **탑다운 (그대로)** |
| `dwell_detector`/`task_manager`/`arm_server` | — | 바뀌지 않음 |
| `target_resolver` | — | **좌표 변환 추가됨** |

`target_resolver`만 손댔습니다. 통합하면 시선은 `map`(SLAM world), 탑다운은
`base_link`로 들어오는데, 변환 없이 비교하면 같은 컵이 수십 cm 어긋나 보입니다
(예: 74cm). 로봇 단독은 두 프레임이 항등이라 이 결함이 안 보이다가 통합하는 날
나타납니다. 지금은 모든 입력을 `base_link`로 변환한 뒤 비교합니다.

탑다운을 **그대로 두는 게 핵심**입니다.
시선은 "어느 컵인지" 고르고, 탑다운이 "정확히 어디인지"를 계속 담당합니다.
이렇게 하면 시선 오차 3cm가 파지 정확도에 영향을 주지 않습니다.

## 순서

**8-1. 융합 코드에 UDP 송신 추가**

기존 저장소 루프 끝에 이것만 추가합니다.

```python
from gaze_udp_sender import GazeUdpSender
sender = GazeUdpSender()                      # 루프 전에 한 번

# ... 루프 안, gaze_point_world() 호출 직후 ...
p_W, origin, ray_dir = gaze_point_world(u, v, D, K, T_WS)
sender.send(p_W, valid=pupil_detected and depth_ok, T_WS=T_WS)
```

> 초안에는 이 자리에 `rotation_matrix_to_quat(...)`를 직접 부르는 코드가
> 있었는데, **그 함수는 이 저장소에 없었습니다**(그대로 붙이면 `NameError`).
> 지금은 `src/fusion.py`에 추가돼 있고, 위 `GazeUdpSender`가 알아서 씁니다.
> NaN/inf 좌표를 걸러내고 송신 실패도 세어 줍니다.

배선만 먼저 확인하려면 합성 데이터를 쏴 볼 수 있습니다:

```bash
python src/gaze_udp_sender.py        # 30Hz로 가짜 시선 송신
```

`valid`를 성실하게 채우는 게 중요합니다. 깜빡일 때 좌표가 튀면
dwell 판정이 계속 깨집니다.

**8-2. 시선 좌표가 들어오는지만 먼저 확인**

```bash
ros2 run gaze_hri gaze_bridge --ros-args -p source:=udp
ros2 topic echo /gaze/point_raw
```

**8-3. `T_BW` 캘리브레이션**

```bash
# 터미널 1 — 캘리브 전용 런치 (전체 런치를 쓰면 안 됩니다, 아래 참고)
ros2 launch gaze_hri calibrate_world_to_base.launch.py source:=udp backend:=feetech
# 터미널 2
ros2 run gaze_hri calibrate_world_to_base
```

로봇팔이 7개 자세를 잡습니다. 매번 **그리퍼 끝을 응시**하세요.
RMSE **20mm 이하**면 통과.

> ⚠️ **전체 런치(`gaze_hri.launch.py`)로 캘리브레이션하지 마세요.**
> 캘리브레이션은 "그리퍼 끝을 응시"하는 작업이라 응시점이 계속 발행됩니다.
> 전체 런치에는 `target_resolver`와 `task_manager`가 떠 있어서 그 응시가
> '집을 물체 선택' → '놓을 자리 선택'으로 해석되고, **팔이 캘리브레이션 도중
> 제멋대로 집기 동작을 시작할 수 있습니다.**
> 위 전용 런치는 필요한 노드(`gaze_bridge`, `dwell_detector`, `arm_server`)만
> 띄웁니다. 캘리브 도구도 위험한 노드가 떠 있으면 경고를 출력합니다.

**8-4. 전체 실행**

```bash
ros2 launch gaze_hri gaze_hri.launch.py source:=udp backend:=feetech
```

탑다운도 같이 쓰려면 `topdown_click`을 `detect_objects: true`로 따로 띄우세요.
마우스를 안 움직이면 물체 검출만 하고 `/objects/poses`를 계속 발행합니다.

# 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 창이 안 뜸 | `camera_index`, `ls /dev/video*` |
| 좌표가 안 나옴 | 캘리브레이션 안 됨. `mode:=calib` 먼저 |
| 좌표가 실제와 다름 | 재투영 오차 확인 → 3단계 재작업 |
| 화면 구석에서만 틀림 | 캘리브레이션 점이 중앙에 몰림. 넓게 다시 |
| 클릭해도 반응 없음 | `hold_time`(2.0) > `dwell_time`(1.2) 인지 |
| 두 번째 클릭 무시됨 | 첫 클릭에서 10cm 이상 떨어진 곳 클릭 (`min_separation`) |
| IK 실패 | 컵을 로봇 쪽으로. 베이스 15cm 이내 도달 불가 |
| 서보가 반대로 돎 | `servo_signs` 해당 항목 -1로 |
| 팔이 처짐 | 부하가 큼. 컵을 가볍게, `l3` 짧게 |
| 카메라 프레임 끊김 | USB 허브 공유. 다른 포트로 분리 |
| 파지 판정이 항상 "빈손" | `grasp_margin` 실측 (6-2) |
| 파지 판정이 항상 "물었음" | 그리퍼가 끝까지 안 닫힘. `gripper_closed` 확인 |
